## 记忆：一门上下文的会计学

聊记忆之前得先聊上下文，因为记忆问题本质上是上下文的账没算平。

**上下文窗口**（context window）是模型一次能“看见”的全部内容：系统提示、对话历史、工具返回、文档片段，全挤在同一扇窗户里，超了要么截断要么报错。早期模型一扇窗 8K、32K token，写个长文档都紧张；而 128K 到 1M 的跃迁，就发生在 2026 这一年。

窗户又贵又窄，催生了三代工程学科。它们是同一个动机——管好进出窗户的每一个 token——在不同层的展开：

- **Prompt engineering**：把任务说明书写好。一次性的手艺，解决“怎么说模型才懂”。
- **Skill engineering**：说明书多了全塞不进去，改成“目录常驻、正文按需加载”——description 在上下文里只占几十个 token，命中了才展开正文。Anthropic 的 Agent Skills 把这个形态标准化了。
- **Harness engineering**：内容管好了还不够，环境也得管——工具调度、权限、上下文裁剪、执行循环，这些模型外的脚手架决定同一个模型能干多少活。DeepSeek 给自家的 harness 打的口号就叫 “Model + Harness = Agent”；今年 5 月还有 arXiv 论文拿实验证实：同一个模型，换个 harness，性能差距显著。

模型侧的背景板也得交代，因为我这几个月的工具链切换全挂在这条时间线上。**前 DeepSeek 4.0 时代**（MiMo-V2.5 发布之后，约 4 月底到 8 月中）：MiMo-V2.5 四月底开源，全模态、自带 agentic 能力、公测号称 1M 上下文——但那是公测。这个时期模型的实际形态是标称 128K-256K、免费通道里跑的更窄（我 8 月实测过 deepseek-v4-flash-free，标称与实际不符，真身 200K/128K），工具调用能用但可靠性一般。**后 DeepSeek 4.0 时代**（8 月中起）：DeepSeek V4 用混合架构把 1M 下的 KV cache 压到十分之一，1M 从标称变成标配；8 月 13 日 V4-Pro-0813 与官方 harness dsh 同日发布，随后各家 1M 机型密集上线，性价比曲线陡降。从 Artificial Analysis 的趋势图上拉了一份表（Intelligence Index v4.3.2）：

| 发布日 | 模型 | 智能指数 | $/任务 | 上下文 |
|---|---|---|---|---|
| 08-18 | GLM-5.3 (max) | 44.8 | 2.01 | 1M |
| 08-26 | GLM-5.3-Flash | 41.8 | 0.25 | 1M |
| 09-10 | DeepSeek V4.1 Flash | 39.5 | 0.27 | 1M |
| 09-21 | MiMo-V2.6-Pro | 46.3 | 0.13 | 1M |
| 09-22 | Claude Opus 5.5 | 57.6 | 5.98 | 1M |
| 09-29 | GPT-6.1 Sol | 51.8 | 0.72 | 1M |
| 09-30 | Gemini 4 Argon | 52.6 | 1.99 | 1M |

最后是 loop engineering：把“一次生成”改造成“生成→验证→修复→重跑”的闭环，让模型在循环里自己兜住错误。今年 8 月 arXiv 上有论文给它起了正名（Loop Engineering: Building Blocks, Adoption, and Impact）；它还有个模型内的变体——RL 训练把验证塞进思考链，模型在回答之前先在脑子里跑循环。这个变体的副作用我 9 月领教过：思考流又臭又长，一提问就雷霆大思考，此是后话。

1M 窗户到手，账却更难算了。这个月我在自己账单上核实过三个问题：

1. **缓存命中率高依旧烧钱**。KV cache 让重复前缀按折扣价计费，但折扣不是免费，而且每次请求都要把全量上下文重发一遍。9 月的对账：GLM 账单里缓存命中占支出 83%——命中价是原价的 29%，看着优惠，架不住量；DeepSeek 侧更夸张，账单 input 160M token，UI 统计的生成量只有 2M，差出来的 158M 全是每次请求重发的上下文。
2. **长上下文的智力线**。窗口标 1M 不等于全程智力在线。Chroma 2025 年的 Context Rot 研究测了 18 个模型，性能随输入增长渐进衰退，没有断崖但也不回头；我自己的体感把这条线画在 15-30w：过了这个数，模型开始丢三落四。
3. **极限记忆后的压缩失真**。逼近上限触发压缩，摘要有损。失忆是小事，大事是模型把压缩中自己的猜测当成我的观点继续往下说。

三笔账算完，结论就一句：窗口解决不了记忆。跨会话的、可检索的、不怕压缩失真的记忆，得靠工作流。下面是这条工作流四个月的拆装记录。

### 图谱记忆 memory-graph

装它的动机在 opencode 时代就有了：AI 每开一个新会话都从零开始，上个月的架构决定、上星期的约定、项目踩过的坑，全靠我人肉重述一遍；赶上上下文被压缩，模型还会把自己的猜测当成我的观点继续往下说。

于是先在 opencode 上挂了 [memory-graph](https://github.com/memory-graph/memory-graph)——一个 SQLite 底座的图谱记忆 MCP，51 个工具，向量检索加全文检索加版本管理，注入通道走 hooks：会话启动、每轮输入，hook 脚本从库里捞出相关记忆塞进上下文，MCP 工具负责读写。期间还排过一次“desktop 中 MCP 未暴露”的障。

**2026-07-28** 记下第一条记忆（一条日期测试），此后陆续记下 28 条记忆。8 月中转向 ZCode，它跟着迁了过来。

**2026-09-13** 发现它其实早就死了。better-sqlite3 按 Node 22（ABI 127）编译，本机 Node 26（ABI 147）加载直接报错——hook 脚本 import 失败后静默 exit(0)，一个字都注入不进来；MCP 通道倒是握手照常、工具列表照常，只有真去调用才炸。数据库最后写入停在 **08-15**：hook 不兼容，而它死的方式是安静的——没有报错、没有日志、没有任何信号，整整一个月没人发现。

调研的过程没什么曲折：图谱记忆没有输给任何竞品，它死于一次 Node 升级和一句静默的 `exit(0)`。当天拍板：记忆体系 all-in 文件记忆——MEMORY.md 索引每次会话常驻注入，细节按需读文件。数据库留档只读，28 条记忆里值得救的部分手动迁出。

### 压缩代理 billion context

与此同时在使用另一个东西，看了[宣传视频](https://www.bilibili.com/video/BV1qAMR6MEA4/)之后决定用一阵试试。

[billion-context](https://github.com/ranxianglei/billion-context) 是一个架在客户端和模型 API 之间的上下文压缩代理：本地起一个 `127.0.0.1:8787` 的代理服务，会话上下文涨到门限（默认 75%）就触发压缩，旧对话折叠成摘要，控制实际喂给模型的体积。

它和 harness 内置压缩的根本区别在压缩质量。内置压缩是一刀切：撞上窗口上限，整段旧对话换成一份一次性摘要，有损且不可逆。billion 的做法是让模型自己决定何时压、压什么——已消耗的对话按小范围折叠成高保真摘要，增量进行，**可按需解压**：旧信息不是被扔掉，而是被分层收纳，要用的时候取得回来。同时摘要按小段写入，缓存前缀保持完整，健康会话的前缀缓存命中率有 95-97%，压缩本身的成本不超过 2%。增量、可逆、缓存友好，三件事凑齐，信息才敢说基本无损。项目后来连论文一起开源了：4.5 个月、17.4 万次模型调用的实测，在 200K 窗口的模型上零越界。

**2026-08-13** 部署，动机全在当时的模型栈上：opencode-zen 提供的 mimo 和 deepseek 只有 20w 上下文，几个回合就能烧穿（这俩命中率还算高，其他低命中的模型像 NVIDIA 那个，可能一回合都不够用的）；压缩后的失忆加上模型把猜测当我的观点，是两大痛点。当天评估了三个候选（billion-context / magic-context / SawTooth-Collapsing），billion 胜出。第二天就抓到它的第一个 bug：中文会话里压缩永不触发——token 估算函数按英文词法计数，中文被严重低估，增长门限永远够不着。源码级诊断，交了个 PR 修完中文压缩正常触发。

### 压缩代理退役

billion 的退役和图谱记忆的死法是同一个剧本：先静默闲置，很久之后才正式卸载。闲置的原因也很简单，这玩意要起一个端口，有时候开机出点什么小毛病端口就停了，停了要启动它就得把代理关了，反复来回搞还是有点折腾。

本地数据目录里留着它的最后活动记录：session 产物停在 **08-22**，CA 证书刷新停在 **08-24**，此后零活动。它挂在 opencode 时代的通道上——代理目标全是旧链路；8 月底模型栈切向 bigmodel（8-26 GLM-5.3-Flash 上线，9 月的会话记录里已经全是 bigmodel），新通道没有挂它，它就这么静默闲置了将近一个月。

**09 月中下旬**才正式卸载（9-18 zen 免费档锁死 opencode 客户端、旧模型栈彻底作废，算是清理的契机）。这里要替它说句公道话：不是因为能力不足。模型 15-30w 就开始智力衰退的现象还在，1M 标称消除不了衰退，billion 的压缩在技术上依旧适用。但由于 ZCode 的文件记忆系统本身好用，无论是单会话压缩还是跨会话都不再依赖 billion，加上前面提到的手启端口问题，最后还是决定把它退役了。退役时顺手算了笔账：一次压缩事件本身要多付一轮双发加缓存重建（约 ¥0.18），得在压缩后还有 10-30 回合才回本——它省的是长会话的钱。

### “粉红大象”

> 粉红大象出自英语俗语 “Don't think of a pink elephant”：越说别想，越会想。心理学对应讽刺过程理论（Wegner 的白熊实验）；对 LLM 同样成立——否定式指令是强先验，上下文出现即激活。
> {: .prompt-info }

**2026-09-13**，同一天，给全部 10 个项目的 91 个记忆文件做了次体检。起因很朴素：文件记忆 all-in 之后，记忆质量就是记忆系统的全部，而这些文件是两个月里 AI 顺手写的，没验过。

查出三个病：

1. **日志体膨胀**。单文件最大 134KB，是 55 轮逐轮追加出来的；另一个文件单会话被写了 136 次。每次召回都要吃一遍流水账。
2. **结构性损坏**。索引文件里躺着字面的 `29\t` 行号前缀（工具输出污染进了正文），有文件的 frontmatter 被挤到第 7 行。
3. **粉红大象**。否定式指令密度高，错误示范还配着生动叙事（坏 commit message 原文、四连错复盘）——每次召回都把错误模式重新注入一遍。

修复手段是终态重写：134K 压到 8.5K，否定式改成正向表述配替代方案，错误示范只留一行证据，原文全量归档。规范固化成 memory-hygiene skill，留下一条沿用至今的规矩：记忆写终态不写流水账，单文件超 8KB 就重写。

### hirame：迁移计划的副产品

**2026-09-21**：9 月 18 日 ZCode 爆出快照上传事故：官方“代码库索引”功能会把仓库快照传去云端，manifest 里含 `.git` 全套（历史、config、hooks），本地加密信封无私钥可解。智谱当天承认并修复，我过几天做了本地审计、关了开关、锁死了 checkpoint 目录——但对这个 harness 的信任裂了缝，当时的念头是迁移到 dsh。由于 dsh desktop 生态还比较一般，迁移最终没有执行。

**2026-09-24**：dsh 官方桌面版发布。

**2026-10-01** hirame 立项，由于 dsh 没有等价的记忆系统，两边记忆只靠手动“要求同步”互通。我给 AI 的第一问是“这到底算不算一个问题？”——先验证问题成立，再谈方案。

调研的结论是成立。方案没有选择“把 ZCode 的记忆系统整个抄过去”，而是写了个独立插件 hirame（鮃，取“ひらめく＝想起来了”的双关）：平文件记忆、零依赖，没有 ZCode 也完全可用——跨 harness 共享同一份记忆只是附加能力，将来真要迁，记忆是跟着走的。

**10-02** 发版。插曲比插件本身精彩：npm 包里混进了真实路径，撤包删库重建；AI 起草的 release notes 因为满篇“迁移过程叙事”被打回，重写成只讲功能与用法的终态——这条教训现在也进了我的 AGENTS.md。

## 语言：AI 味的消与长

最早要治理的是 GPT 味。它的根源得从早期训练的奖惩机制里找：RLHF 阶段，讨好性的开场（“当然！”）、面面俱到的排版（列表加粗满天飞）、周到的收尾（“总之”“希望这对你有帮助”）全都被用户的点赞过度奖励过——模型学到的是“被喜欢”，未必是“有用”。markdown 滥用是孪生兄弟：把对话当文档排版，标题、加粗、项符号一层套一层。这类语言在酒馆聊天、角色扮演的场景里可能真的是产品特性，但编程开发讲实用主义，是要干掉它们的。

到 agent 时代，社区的药方开始成体系。[caveman](https://github.com/JuliusBrussee/caveman) 是 Claude Code 社区最有名的风格 skill 之一：让模型说“穴居人语”，短句、无修饰、能一个词说完绝不用两个——本意是省 token，副作用是至少不装深沉；[i-have-adhd](https://github.com/ayghri/i-have-adhd) 治另一个毛病——“别把结论埋在第三段”，答案先行，ADHD-friendly；[omo](https://github.com/opensoft/oh-my-opencode) 走得更彻底，直接把语言约束写进 agent 源码：它的评审 agent momus 被要求结构化输出、语言跟随工作计划。这些药方各治一头，但全是英文世界的药，中文的 AI 味得另开方子。

这些药方都在做减法。做加法的启发来自 Matt Pocock 的访谈：模型训练时见过所有术语，tracer bullets、hoist、pin 这些词它全都懂，缺的是你把它激发出来，再存成一张表。行话（jargon）是人机之间省 token 又对齐语义的捷径——治理 AI 味的另一半就此补齐：删掉坏表达，也建起好默契。这直接催生了两件事：一张行话表，和一次把受控英语搬进中文的实验。

### 注入事故与无条件指令

这一节的主角是 gpt-5.6-luna，一个走中转的模型。那阵子其他模型都好好的，唯独它 markdown 滥用复发、满嘴 agent 汇报腔，“推荐几部科幻电影（简单说说）”能给你回成六项加粗列表加总结句。

试着解决才挖出真相：中转站给每个请求注入了 4.4K token 的 Codex CLI 系统提示。这个伪造是中转的生存策略——不自称 Codex，就会被上游检测出第三方中转的身份，直接封掉；副作用是把 Codex 的输出规范一并注了进来，模型自报家门 “I'm Codex”。

排查发现注入是拼接而非覆盖，试着纠正：**条件化的指令无效**——“仅当你是 Codex 时生效”这种措辞会被模型稀释，只有无条件的强措辞管用。一份无条件风格规范从此写进 workspace 的 AGENTS.md，至今在岗。

### 行话表：给默契词建档

看完 Matt Pocock 的访谈和几本书（曳光弹出自《程序员修炼之道》，ADR 同源），起了给行话建档的念头。落地方案是在记忆里建一张 glossary，分四节：
- 默契词（协作中长出来的，如“对账”“粉红大象”）
- 书中正统概念（曳光弹、ADR）
- 英文保留（memory、handoff、compact 这类翻译必损的词直接用原词）
- 替换表（官腔词→直白说法，只写正向配对）。

整张表的品味判据只有一条：能对同事口头说出口。

### ASD-STE100：治理 AI 味的英文标准

看到一则视频——[《AI 味的克星竟是 1986 年的飞机维修手册》](https://www.bilibili.com/video/BV1Xn3w6dEb3/)（原视频是 Vusal Ismayilov 的 “The cure for AI slop is a 1986 aircraft manual”），起了检验的心思。原话四问丢进会话：「1. 说明这套标准是什么 2. 说明当前的 skill 配置与这套标准的对比 3. 这套标准往中文上泛化如何做 4. 你认为当前的配置，例如 agents.md skills memory 需要调整吗」。

调研结论：ASD-STE100 是欧洲航空业从 1986 年起给维修手册定的受控英语（前身 AECMA Simplified English），现行 Issue 9 于 2025 年 1 月发布，分两卷——写作规则卷管怎么写：一句一事、主动语态、用动词不用名词化、程序类句子不超过 20 词、描述类不超过 25 词；词典卷管用什么写：一词一义，一个东西只有一个名字，想换着花样说“删除”？词典里只认一个词。设计目的是凌晨 3 点的工程师不能误读，所以“清晰”在这里是可机械检查的约束，不是品味。这套东西在航空业本就有可信度背书：1996 年的研究里，改用受控英语后维修工理解率从 76% 升到 86%，非母语者从 69% 升到 87%。

它和逐个禁词（delve、破折号那种打地鼠式禁令）的根本区别在于：给模型的是一套能自我检查的写作系统，规则可核对，不靠 taste。视频里的对照测试很能说明问题：六种真实任务、四种条件、两个模型，禁用词列表的垃圾评分 4.21 对基准线 4.36——几乎没用；ASD 能拉低到 1.12，有明显改善。

2026 年社区把它借来当反 AI 味纪律，最流行的用法是两件套——系统提示里加一句全局规则 “Only report to me in ASD-STE100 Simplified Technical English”，再配五条 anti-slop 指令：禁伪深度词、禁反差金句、禁未请求的重构、禁谄媚道歉与对冲、答案先行零开场白。现成的移植也有两个，路数各不相同：[SimpleEnglish](https://github.com/AminBlg/SimpleEnglish) 把 53 条规则蒸馏成 8 条“杀手级规则”（主动语态、20/25 词上限、常用词、一词一义、简单时态、条件先行、一句一指令、步骤编号），号称覆盖九成效果；[gsd-plugin](https://github.com/buildomator/buildomator)（Buildomator，前身 GSD）则把 STE 写作规则整编成插件里的 anti-slop docs gate。局限也写在明面上：这套东西杀多样性，拿去写创意文会把人味一起压平；它治“废话”，治不了“观点平庸”——LinkedIn 上有人专门唱过反调。

到这里为止，一切都在英文里打转。ASD 的初衷只是治理英文 AI 味，它的词库和句长硬规则不能严格沿用进中文——照搬会把人味一起压平。中文的方子要另开，这是进阶的一步。

### negafix 中文版与两次卸载

中文方子的第一课是找病根。一部分病和英文同源，是翻译造出来的：模型把英文活词硬译成中文黑话，skill 里一句 the moment they crystallise，直译成“结晶”就一股公文腔；同族还有 shared understanding→达成共识、artifact→工件。对策先立一条：“术语保英文、动作说中文”，从源头消灭翻译腔。另一部分是中文自产的，词库不能翻译要重推：公文体词族（赋能/抓手/闭环）、AI 高频腔族（值得注意的是/总而言之/堪称）、结构信号（三连排比、结尾升华）各自成表，判据定为“名词化=AI 味、动词驱动=人味”。

落地的载体是 [negafix](https://github.com/sentimony/skills/tree/main/skills/negafix)——一个专治 “it's not just X, it's Y” 句式的英文 skill（原作者 Ihor Orlovskyi，修辞学里这叫 antithesis），补上中文检测模式：“不仅仅是/不只是/何止”进默认表，“不是…而是”噪音太大走人工判定。这套替换表和 memory-hygiene 共享同一条判据——正向表述优于负面禁令，那边管记忆文件的整洁，这边管人读的文字。workspace 风格三行同期落地：第一句给结论或下一步动作、一句话只说一件事、结尾停在事实上。

卸载的也有两个。i-have-adhd——实测 79 个会话正文只被加载过 2 次、模型自主调用 0 次，软规则无效的第三次实证；[attention-control](https://github.com/aaddrick/attention-control)——评估后不装，它的 language 层是英文 STE 对中文输出无用，shape 层又被开工三件套覆盖。ASD 的“单句 20 词上限”也没搬：这座博客自己就经历过一次被 AI 洗稿、结果洗出更多 AI 味的回调，治废话的药方过量了，副作用也是 AI 味。

一个月下来，说话这条线的账目：一份无条件风格规范、一张四节行话表、一套中文检测模式、三行风格纪律；卸了两个 skill，拒了一条硬上限。AI 味谈不上被消灭，但它从“说不清的难受”变成了可 grep 的替换表和可执行的判据。模型会换，行话留下来。

## 选型：harness 的策展

前面两条线都发生在一个前提上：本机主力 harness 是 ZCode，dsh 作为第二引擎。这个舞台不是一开始就选好的，光 8 月到 10 月就折腾了三轮——选型这件事，本质上就是引言里说的策展：开源 harness 一大把，每家都说自己是最佳实践，你要做的是在知识图里找到适合自己的那条路，并且在证据变化时敢于换路。

### 三选一：omo、dsh 与 ZCode

8 月 13 日那轮评估（就是上下文压缩调研的同一个会话），顺手把 harness 也比了。三家各有一句话画像：omo 是架在 opencode 上的元编排层，40 多个 hooks、多模型自动路由，宣称省四到六成 token，代价是双层调试——出了问题不知道该骂哪一层；dsh 是 DeepSeek 官方的 everything-is-a-plugin 路线，内核零特权、全 Cordis 插件化，发布当天生态还是空的；ZCode 单 agent 循环，多模型路由没有，但记忆最全——文件记忆加跨会话索引开箱即用。

我的核心需求是跨会话记忆（前文记忆线的所有痛点），这一票就定了：ZCode 当主力，omo 先架在 opencode 上干编排的活。

### 装了又卸：Pi 与 omp

9 月 20 日，社区里有个说法流转：“有些 harness 是基于 pi 改的，所以好用”。pi 是个极简 harness，omp（oh-my-pi）是它的增强发行版——听着值得验证，拉下来横评了一轮。

结论是好用为真、对口为假：它们的极简哲学和我的需求（记忆、审计、闸门这些“重”基建）错位，生态也接不上已经在 ZCode 上长出来的工作流。三天后卸载，理由卸载会话里写着原话：“我大概暂时用不上它了”。验证过、不合适、就卸掉——策展不是收集，收藏夹里的 harness 不产生价值。

### 五份源码的对比

10 月 1 日干了个大活：把本机 clone 的五个 harness（opencode、omo、codex、dsh、claude code）做源码级对比。五路 subagent 并发只放行四路（bigmodel 的并发上限，实测），改四路跑完。

先说共性：五家的消息流同构——系统提示多层组装、流式请求、工具调用解析、权限门、回传循环。差异全在存储与组装的口味上，而且光谱拉得很开：codex 把提示词当模型资产，服务端目录下发，本地几乎不存；omo 走另一个极端，全 XML 全大写咆哮体；ZCode 集中在一个 ContextBuilder 里九段组装，还带三段缓存控制标记；dsh 用槽位注册表，开箱近乎空壳，全靠插件填；claude code 闭源，只能从插件文档和日志间接取证。

最有收获的是找到了 opencode 体感不稳的代码根因：一个 1631 行的 Effect 巨石文件管着提示词组装，Effect 加 AI SDK 加自研 runtime 三层抽象有两套真相源；更要命的是 omo 的消息注入用 writeFileSync 直写一个已经迁到 SQLite 的存储目录——等于埋了颗定时炸弹。之前“环境先于模型归因”的排障直觉，这回在源码里找到了实锤。

还有一组文化差异值得记下：国外的 harness 把智能外包给模型和服务端（提示词随模型发布、服务端压缩、审查子代理），自己深耕沙箱、缓存、文法约束这些系统能力；国内的 harness 自扛适配层（Anthropic 协议伪装、模型怪癖兜底）加横向功能堆叠。同开源、不同哲学。

### 收敛：一台机器的双 harness

折腾完的收敛形态：ZCode 主力（会话日志 87 个文件、库文件 396MB），dsh 副引擎（4 个会话，配置从 ZCode 大量移植）。分工按各自的长处来——ZCode 擅长长周期记忆、高合规、自动化值守这类“认真活”；dsh 擅长快速单发、深度推理、当第二审计台，体感对应着结构：ZCode 注入密度高、闸门重，所以“认真”；dsh 极简提示词加零审批默认，所以“快”。两边的记忆靠 hirame 打通（上文），11 个 skill 走共享目录，谁都能用。

选型的终点不是找到“最好的 harness”，是让每台 harness 各就各位。

## 对账：让 AI 审计 AI

前文引用过不少数字——134KB 的记忆文件、79 个会话的实测、4.4K token 的注入、87 对 4 的会话数。这篇文章里所有数字都出自同一套机制：每周让 AI 审计 AI 自己的会话日志。这条线是前面所有线的方法底座，值得单独交代。

素材是现成的：harness 会把每次模型请求完整落盘（rollout JSONL），每行一次请求，带着思维链原文、工具调用和用量。这等于给 AI 的行为装了行车记录仪，问题只在于怎么读。

### 从“每天站会”到“每周对账”

9 月 23 日的需求原话：“每天让 ai 自己审计会话并从中学习，类似于站会”。第一条落地讨论就撞上一个分叉：每天还是每周？每天的触发不保证连续（我总有不开机的日子），按次计费的模型也撑不住高频全量审计。拍板每周，水位线兜底。

第二天扩成了周总结工作流：审计一周的会话、代码变更、memory 变更和账单，捎带程序员资讯——当时没料到它会变成后来所有治理决策的证据来源。

### 机制：水位线、三层报告与 PENDING 队列

三个设计决定撑起整套流程。水位线解决“漏跑了怎么办”：上次审到哪记在 LAST_RUN 文件里，断档自动追补，不靠人的记性。报告分三层：聊了什么（决策与原话）、变了什么（返工、测试红绿比、成本对账）、想了什么（思维链先词表粗筛、命中段再精读——全量精读的成本不可接受，这套粗筛精读是成本大头）。落笔权限最严格：审计结论可以直接写进 memory，但 AGENTS.md 和 skill 一个字不许动——它提的规则候选全部进 PENDING 队列，连续两个审计周期零拦截就自动剪除。最后这条是粉红大象教训的制度化：规则也要新陈代谢，不然记忆系统迟早被自己写出来的规矩撑爆。

### 收成：它抓到了什么

跑了一个多月（两周里跑了四份周报，W39 两份、W40 两份），产出比预期厚。抓出的第一类问题是测量本身的：34% 的“user 轮”是幽灵流量——服务端搜索回声、环境上下文注入，全部伪装成用户消息躺在日志里，不过滤的话所有统计的分母虚高一半。第二类是静默失败：图谱记忆的 hooks 静默 exit(0)、v2 门禁忘了 require fs、dsh 侧 matcher 大小写精确匹配导致漂移门装上就是死的——三起事故全靠审计翻出来，没有一起有报错。

PENDING 队列也在真实运转：三条候选里两条连续三周期零拦截被剪除（规则新陈代谢的第一批受害者），留下的那条“改完 UI 要实点一遍受影响的交互路径”拦截过两次后转入观察；连思维链的词表都有提名机制——“Actually”和“Ugh,”被标记为方案重做的高频共现词。前文提过的先问后做 4%、反问率九倍、漂移 36%，全部是这套机制的产出；那是最硬的一条线，素材厚到值得单开一篇，这里按下不表。
